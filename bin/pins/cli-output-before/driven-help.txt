===== xchain-node bootstrap --help =====
Usage: xchain-node bootstrap [options] <action> <service> <chain> <network>

Create / Restore XChain service bootstraps

Arguments:
  action         (create, restore)
  service        (xchain-decoder, xchain-utxo-tracker, xchain-indexer,
                 xchain-hub)
  chain          (bitcoin, litecoin, dogecoin)
  network        (mainnet, testnet, regtest)

Options:
  --latest       restore the newest bootstrap without prompting (scriptable)
  --file <name>  restore this exact bootstrap archive without prompting
  -h, --help     display help for command

Notes:
    bootstrap create  - generates a bootstrap file
    bootstrap restore - restores a bootstrap file

    restore prompts only on a TTY. With --latest, --file, or no TTY it
    resolves non-interactively, so a script cannot wedge on an unanswerable
    menu while holding the command lock.

===== xchain-node bootstrap-combos --help =====
Usage: xchain-node bootstrap-combos [options]

List served <service>:<coin>:<network> combos, one per line (scriptable)

Options:
  -h, --help  display help for command

Reads the module registry, not live containers, so a STOPPED or crash-looping
combo is still listed. scripts/publish-bootstraps.sh --all builds its plan from
this: detecting from `docker ps` dropped stopped combos before the source-health
gate could report them, so the cron exited 0 while a consumer archive went stale.

===== xchain-node bootstrap-republish-due --help =====
Usage: xchain-node bootstrap-republish-due [options]

List combos whose published bootstrap predates their last reindex (scriptable)

Options:
  --json      emit the full records (reindexedAt, publishedAt, reason) instead
              of bare combos
  -h, --help  display help for command

A reset wipes a store and rebuilds it on a NEW lineage, so every bootstrap
already published for that combo describes the old one: a fresh install that
takes it restores pre-reindex state and halts. Nothing forced a republish, and
no age check catches it, because the stale-lineage archive is hours old and
simply wrong.

`reset` records the combos it wiped, `bootstrap create` records what it
re-derived, and this lists the difference. scripts/publish-bootstraps.sh reads
it to pull due combos into its plan even when the schedule or the tracker
opt-in would have skipped them.

                   clear
  -h, --help       display help for command

Usage: xchain-node update [options] [service] [chain] [network] [ref]

Update XChain services (and the CLI itself) to the latest release, or to a named
